# 06 业务流程分析

> 本章按 **真实智慧园区运营业务** 梳理，不按代码包结构。  
> 依据：后端 Service 行为、前端页面路径、数据表关系与项目文档。

---

## 业务总图

```text
获客(招商/CRM) → 看房/意向 → 签约入驻 → 房源占用
                              ↓
                    月度账单生成(人工/导入/AI)
                              ↓
                    催缴 → 收款 → 核验 → 财务入账
                              ↓
              合同到期提醒 → 续租/退租 → 空置再招商

并行：门禁访客、运维巡检报修、员工考勤薪酬、数据看板、企业开通SaaS
```

---

## 1. 用户登录流程

### 1.1 业务目标

运营人员/管理员安全进入指定 **企业租户** 的园区管理系统，并获得菜单与园区数据范围。

### 1.2 流程步骤

```text
1. 打开登录页（PC / App）
2. 选择登录方式：
   A. 用户名或手机号 + 密码
   B. 手机号 + 短信验证码
3. 后端在中心库校验：
   - 用户存在且启用
   - 所属 customer 已开通且未停用
   - 密码或验证码正确
4. 建立会话：
   - 签发 Access Token（含 customerId/dbName/userId）
   - 签发 Refresh Token（Cookie）
   - 可选图片访问 Cookie
5. 前端拉取：
   - GET /user/info
   - GET /auth/codes
   - GET /menu/all
6. 进入首页/工作台，后续请求经 AuthFilter 注入 TenantContext
```

### 1.3 关键业务规则

- 对外统一「用户名或密码错误」，避免账号枚举  
- 企业未开通/停用单独提示  
- 密码可能中心库与租户库双写修复（迁移兼容）  
- 高敏操作（催缴）需额外页面验证码  

### 1.4 涉及系统点

`AuthService`、`JwtService`、中心库 `user/customer`、租户库菜单权限、Redis 验证码

### 1.5 断点/风险

- 中心与租户用户数据不一致  
- Refresh 与多端登录策略需产品明确

## 2. 园区管理流程

### 2.1 业务目标

建立可运营的园区主体，作为房源、租户、账单、权限的根维度。

### 2.2 流程步骤

```text
1. 超级/企业管理员创建园区（名称、地址、面积、联系人、状态）
2. 配置园区图片与基础信息
3. 为角色/用户授权可管理园区（role_park / user_park）
4. 在园区下维护厂房与楼层（面积、租金、消防电梯等）
5. 运营侧「园区管理」页面持续维护库存
6. 仪表盘按园区聚合出租率、营收、能耗
```

### 2.3 业务规则

- 无园区授权则业务列表为空或拒绝  
- 园区软删（is_deleted）后应不可再选  
- 访客登记使用 visitor-list 子集  

### 2.4 输出物

园区主数据 + 可租库存基础

## 3. 企业入驻流程

> 这里的「企业」指 **入驻租户企业**（非 SaaS 客户）。

### 3.1 业务目标

将意向客户转化为在园租户，占用房源并具备计费资格。

### 3.2 主路径 A：招商转化

```text
1. 招商登记/雷达线索跟进（investment）
2. 带看、意向确认、商务谈判（跟进反馈、拜访、SOP）
3. 执行 convert-to-tenant
4. 生成 rental_tenant（合同起止、递增、联系人、园区）
5. 关联/占用厂房楼层面积
6. 后续进入账单计费
```

### 3.3 主路径 B：直接建档

```text
1. 合同管理页直接新建租户
2. 填写企业名、电话、地址、合同期、递增条款、状态
3. 上传合同/证件图片
4. 保存后成为计费对象
```

### 3.4 业务规则

- 租户必须归属园区  
- 状态字段表达在租/退租等（字符串枚举，约束弱）  
- 合同到期提醒依赖 contract_end + 提醒视图 backfill  

### 3.5 缺口

- 缺少标准「入驻审批单」与电子签  
- 押金/保证金流程不完整  
- 房源占用与合同缺少强事务一致性

## 4. 招商流程

### 4.1 业务目标

持续获取潜在入驻企业，管理销售过程，提高去化率。

### 4.2 双引擎

**引擎 1：人工登记（传统）**

```text
渠道/中介推荐 → 登记 investment → 设意向等级/面积
→ 跟进反馈 → 进展推进 → 转租户或关闭
```

**引擎 2：招商雷达（数字化获客）**

```text
配置爬虫源 → 采集任务 → 信号事件/公开商机
→ 清洗为 external_lead → 评分 → 分配销售
→ 触达（模板审批/发送）→ 跟进拜访 SOP
→ 房源匹配 → 转化租户
并行：联系限制合规名单控制触达
```

### 4.3 CRM 辅助

```text
销售活码/小程序码 → 扫码 → 客户绑定销售
→ 企微外部联系人回调增强客户档案
```

### 4.4 关键指标

中介统计、渠道分析、销售漏斗、模板效果（radar analytics）

### 4.5 业务问题

- 线索模型双轨（investment 表 vs lead 表族）  
- 雷达运维重，业务与技术耦合  

---

## 5. 合同签约流程

### 5.1 业务目标

固化租赁法律关系与计费条款，成为账单与提醒的源头。

### 5.2 流程步骤

```text
1. 确定租户主体与园区/房源
2. 录入合同起止日
3. 录入租金递增日、递增率
4. 录入联系人电话（催缴/通知用）
5. 设定状态（在租等）
6. 保存 rental_tenant
7. 合同期内：
   - 变更条款（更新记录）
   - 到期提醒（列表 contractView）
8. 到期后：续租（改 end 日期）或退租（改 status）
```

### 5.3 与周边流程关系

| 下游 | 依赖合同字段 |
| --- | --- |
| 账单 | tenant_id、园区、项目名习惯 |
| 催缴 | 电话 sms-info |
| 看板 | 合同统计、到期数 |
| 工资 | 历史误挂（租户维度发薪） |

### 5.4 真实园区业务缺口

- 无多房源/多条款拆分  
- 无合同编号与归档编号体系  
- 无变更协议版本链  
- 无标准退租结算单（违约金/押金退还）

## 6. 账单生成流程

### 6.1 业务目标

按账期生成租户应收：租金 + 物业/服务 + 水电 + 税费等。

### 6.2 三条生成管道

#### 管道 A：人工制单（主路径）

```text
1. 选择园区 + 租户
2. 拉取 latest-template（继承表计名、单价、公式）
3. 录入/确认：
   - 电费明细（上期/本期读数、倍率、单价）
   - 水费明细
   - 厂房租金、管理费、服务费、发票税
4. 系统汇总 total_fee
5. duplicate-check 防重复账期
6. 保存 amount_bill + ele_bill + water_bill
```

#### 管道 B：Excel 导入

```text
上传工作簿 → 建 batch → 解析 sheet
→ 生成 candidate → 问题检测/AI 辅助
→ 人工纠正与确认 issues
→ publish 写入正式账单
→ 可 rollback
```

#### 管道 C：AI 识别

```text
上传历史收费通知单 Excel/文件
→ AI/规则抽取金额与租户名
→ 匹配租户（可自动创建占位租户）
→ 置信度达标可自动入账，否则人工 commit
```

### 6.3 业务规则

- 园区授权过滤  
- 零金额可配置跳过（AI）  
- 收款前账单可改删（需权限）  

### 6.4 痛点

- 费项靠宽表字段扩展  
- 账期语义弱  
- 智能表自动出账未完全闭环（仍偏人工/导入）  

---

## 7. 收费流程

### 7.1 业务目标

确认租户已支付某期账单，更新收款状态并沉淀财务。

### 7.2 流程步骤

```text
1. 财务/园区管家在账单列表筛选未收款
2. 打开确认收款页 /bill/receipt-confirm
3. 登记收款时间等信息 → PUT receipt
4. 触发/关联：
   - 账单 receipt_time 非空 = 已收
   - 可能生成/同步 finance 流水
   - 可能创建 rent_verify_task 进入核验
5. 核验人确认或打异常
6. 报表侧营收统计读取已收账单/流水
```

### 7.3 支付通道

- 当前主体仍是 **线下收款后系统登记**  
- 微信支付/支付宝更多服务 VIP 会员等场景，非主流租金收银台  

### 7.4 业务规则

- 收款是账单生命周期关键节点  
- 部分收款/拆分支付支持弱  

---

## 8. 催缴流程

### 8.1 业务目标

对逾期/未收款账单触达租户，提高回款率。

### 8.2 流程步骤

```text
1. 筛选未收款账单
2. 检查催缴通道 readiness
3. 预览短信内容（preview）— 只读
4. 高敏二次验证：
   - 发送页面验证码
   - 校验获得 page-access proof
5. 确认发送 collection-sms/send
6. 租户收到短信 → 线下/约定方式缴费
7. 回系统做收费流程（第 7 章）
```

### 8.3 业务规则

- 必须登录且有园区权限  
- 短信模板/通道依赖联麓配置  
- 预览与发送分离，降低误发  

### 8.4 缺口

- 缺少催缴工单、催缴频次策略、升级（电话/上门）记录  
- 缺少账龄分析与自动催缴调度产品化

## 9. 数据分析流程

### 9.1 业务目标

管理者掌握出租、合同、回款、能耗与待办，驱动运营决策。

### 9.2 流程步骤

```text
1. 登录后进入分析看板/工作台
2. 选择园区与时间范围
3. 后端聚合：
   - 厂房出租统计
   - 合同统计（在租/到期）
   - 客户概览
   - 营收统计
   - 水电能耗
   - 工作台待办（核验、审批、提醒等）
4. 支持 overview-batch 一次拉取多指标
5. 招商侧另有 radar analytics 漏斗
```

### 9.3 数据来源

| 指标 | 主数据 |
| --- | --- |
| 出租率 | factory_floor used/total + 租户 |
| 合同 | rental_tenant |
| 营收 | amount_bill receipt / finance |
| 能耗 | ele/water 明细或第三方表计 |
| 待办 | 多模块状态拼装 |

### 9.4 问题

- 实时 SQL 聚合，大数据量园区会慢  
- 指标口径分散在多个 Controller  
- 缺少主题仓/指标字典

## 10. 其它关键业务流程（简）

### 10.1 SaaS 企业开通

```text
购买/创建组织 → provisioning job → 建库建管理员
→ 事件通知 → 成员邀请加入 → onboarding
```

### 10.2 报修与巡检

```text
发现问题 → 报修工单/巡检登记（可外链）
→ 处理更新 → 归档
```

### 10.3 访客通行

```text
访客填写登记（可公开）→ 园区审核/放行状态 → 台账查询
```

### 10.4 员工考勤薪酬

```text
员工入职建档 → 定位打卡 → 请假 → 考勤汇总 → 工资草稿 → 发放同步财务
```

## 11. 端到端「园区运营日」故事

```text
晨会：看工作台待办（到期合同、未收款、核验异常）
上午：招商跟进线索；管家确认访客
午后：抄表/导入账单/AI 制单；发送催缴
傍晚：登记收款并核验；更新财务
夜间：定时任务处理导入清理、outbox、同步类 job
```

## 12. 流程 maturiy 评估（旧系统）

| 流程 | 成熟度 | 说明 |
| --- | --- | --- |
| 登录多租户 | 高 | 生产可用 |
| 园区房源 | 中高 | 模型偏简 |
| 入驻签约 | 中 | 缺合同域完整 |
| 招商 | 中高（功能多） | 结构乱 |
| 账单生成 | 高（三管道） | 模型待规范 |
| 收费 | 中 | 偏登记制 |
| 催缴 | 中 | 有短信缺策略 |
| 数据分析 | 中 | 缺指标中台 |
| 支付线上化 | 低-中 | 非租金主路径 |

---

## 13. 对新系统流程设计的启示

1. 以 **合同 + 账单 + 收款** 为运营主链，其它模块插件化。  
2. 招商转化必须事件化进入合同域。  
3. 催缴应产品化为「收款工作台」而不仅是发短信。  
4. 数据分析应独立只读模型，不拖垮交易库。  
5. 每个流程定义显式状态机与审计日志，消灭隐式字段约定。
